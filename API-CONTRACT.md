# Shared implementation contract

The primary user flow now uses automatic matchmaking. See [MATCHMAKING-CONTRACT.md](MATCHMAKING-CONTRACT.md) for queue endpoints, the additional `matchmaking` bootstrap field and generated course-plus-number squad names. The manual matching and squad-creation endpoints below remain available for compatibility; they are no longer the primary UI flow. Client-provided squad names are ignored in favor of the generated name.

Meeting readiness and automatic Google Meet creation extend this API: see [MEET-CONTRACT.md](MEET-CONTRACT.md). Upcoming conference URLs are withheld until every current member is ready; dashboard meetings include readiness state and the dashboard includes Google connection availability.

Weekly release, sequential lesson access and the compact learning workspace are described in [PROGRESSION-CONTRACT.md](PROGRESSION-CONTRACT.md). Public course metadata contains previews only; authorized dashboard lesson material is filtered by the requesting learner's access.

Current courses also require lesson quizzes and individual weekly assignments. Quiz scoring, submission validation, migration credits and the two new endpoints are defined in the progression contract. `/checkout` is a free demo order-summary page before matchmaking; no real payment is processed.

All JSON endpoints are same-origin under `/api`. Errors: `{error: string, code?: string, conflicts?: array}`. Real SQLite persistence with server-derived identity in HttpOnly cookie. Plain English UI, white panels and borders. No fake users in normal data. Node 24 native `node:sqlite`, React + Vite + Luxon. Backend listens 3001; Vite proxies `/api` to it. Production backend serves dist on 3001. All dates ISO UTC strings, availability local IANA zone. Level `beginner` or `basics`, with course-specific labels and descriptions. Active track IDs are `python`, `ai-literacy`, `spanish`; `ai` remains archived for existing squads and history; `javascript` is removed from the product.

Bootstrap `tracks` lists active courses; `archivedTracks` supplies only legacy AI Apps metadata. JavaScript is removed: startup closes its unfinished sprints, deactivates memberships and clears that course selection and search queue, preserving guest identity and availability. Its squads are excluded from history; authorized direct workspace reads/writes return 410 `course_removed`, and the client redirects to a current squad or course selection. Stored old work remains in the database for recovery. Course metadata includes `shortTitle`, `category` and `levels`. New searches and squads accept active courses only. Existing archived AI members can keep their course while editing their profile; saved plans, tasks and meetings are not rewritten. New plan tasks may include `steps` and `practice` string arrays, an `example` string, and an `extension` challenge for learners who know the basics. Clients must also support historical plans without these optional fields.

## Data
Profile: `{id,name,trackId,level,timezone,availability:[{day:1..7,start:'19:00',end:'22:00'}]}` (Mon=1). A new guest may have blank profile fields.
Public track: `{id,title,description,project,prerequisite,weeks:[{week,title,lessonCount}]}` plus course-specific level metadata. Stored plans have exactly 8 stable tasks; ids `week-1-task-1` etc. Criteria is a string. Two tasks per week. Public previews never include tasks or teaching material.
Squad summary: `{id,name,trackId,level,status,memberCount,capacity:4,members:[{id,name}],meetings:[{id,startsAt,endsAt,windowEndsAt,topic,week}],startDate,endDate}`. `endsAt` = 50 minutes; `windowEndsAt` = 60 minutes. States `forming`, `ready`, `active`, `completed`, `closed`.
Dashboard: `{squad: summary, members:[{id,name,isSelf,active}], meetings:[{id,startsAt,endsAt,windowEndsAt,topic,week,meetUrl,organizerName}], plan:{source:'base'|'ai',weeks:[{week,title,preparation?,access,tasks}],message?:string}, learningProgress:{done,total,nextTaskId,nextAvailableTaskId,nextReleaseAt}, progress:[{taskId,status:'not_started'|'in_progress'|'done',note,url}], teamProgress:[{userId,name,done,total:8,results:[{taskId,status,note,url,locked?}]}], isMember:boolean, canEdit:boolean}`. Each task has `access`; locked tasks contain only identity, title and access, while unlocked tasks include their teaching fields and optional `lesson`. See the progression contract for field details. Departed members can read their history but cannot edit. `teamProgress` is visible only to current/former authorized members, with notes/links withheld for tasks locked to the viewer. Client displays own progress independent of team.

## Endpoints
- GET `/api/bootstrap`: `{user:profile|null,tracks:Track[],currentSquadId:string|null,history:summary[],aiAvailable:boolean}`. No automatic guest creation.
- POST `/api/session`: create guest if needed, return same bootstrap.
- PUT `/api/profile`: full profile input (no id), optional `confirmConflict:true`; validate 2 hour windows on distinct days, half-hour increments, merged adjacent availability and course-specific levels. Practical AI accepts beginners; only the archived AI Apps course requires Python basics. Conflict with current schedule returns 409 `schedule_conflict` unless confirmed; does not reschedule team. Changing track/level while unfinished membership should be rejected.
- GET `/api/matches`: `{squads:summary[],cohortStart:string}` max 3, real matching on ALL 8 windows, sorted first groups with 2 members then earlier.
- POST `/api/squads/preview`: `{slots:[{day,start},{day,start}]}` -> `{meetings:summary.meetings,startDate,endDate}`. Next Monday cohort, concrete 8 dated meetings.
- POST `/api/squads`: same slots, optional name -> `{squadId}`. Validate preview again and create with self. Stable base plan saved with sprint.
- POST `/api/squads/:id/join`: `{}` -> `{squadId}`. Transactional, idempotent; capacity and availability checks.
- GET `/api/squads/:id`: dashboard (members/history only; no private data to outsiders).
- POST `/api/squads/:id/leave`: `{}` -> `{ok:true}`; preserve history.
- PUT `/api/squads/:id/meetings/:meetingId`: `{url}` -> `{ok:true}`; exact https meet.google.com link or empty to clear, member only.
- PUT `/api/squads/:id/progress/:taskId`: `{status,note,url}` -> `{ok:true}`; own progress only, validated optional http(s) link. Server checks calendar and prior-lesson completion; locked writes return 409 `lesson_locked`.
- POST `/api/squads/:id/adapt`: `{}` -> `{source,message}`. Server-configured AI adapter, safe base fallback; never rewrite a plan with started work; only once successful; rate limit. No secrets sent to browser.
- GET `/api/health`: `{ok:true}`.

Backend module exports `createApp({dbPath,now,aiAdapter}={})` -> `{server,db,close}`. `server` is node http.Server (not listening); test uses server.listen(0). `now` injected returns Date. `aiAdapter` optional async function receives base plan + track/level and returns weeks; validate output. `server/index.js` starts default app. Database at env DB_PATH or data/learning-squads.sqlite. Never seed automatically. FRONTEND fetch helper attaches credentials and JSON. Export backend pure scheduling functions if convenient for tests; HTTP integration tests primary.

No payment processing, compulsory registration, chat, code execution or actual attendance tracking. Automatic Meet creation requires the optional Google OAuth setup. Price informational $29; no charges in MVP. Explain guest cookie recovery limits; Practical AI needs no API account, while the archived programming course retains its mock mode and optional paid API caveat. Use native accessible dialog or inline confirmations, clear loading/errors/success.
# Profile extensions: city, avatar, independent learning

`PUT /api/profile` additionally accepts optional `cityId` and `learningMode: "squad" | "solo"` (omitted means squad). A selected GeoNames ID determines `timezone` and `cityLabel` on the server; submitted labels or conflicting time zones are not trusted. Unknown IDs fail validation. Manual named time zones remain supported. Solo profiles need no meeting availability. An active course fixes its learning mode, course and level.

`GET /api/cities?q=...` requires a guest session, accepts 2–100 characters and returns `{cities:[{id,name,label,timezone}]}` with at most eight results. Offline GeoNames aliases support multiple scripts. Limit: 90 requests per minute per guest.

`PUT /api/profile/avatar` accepts raw JPEG, PNG or WebP bytes, not JSON; guest session and same-origin mutation checks apply. Maximum server input 2 MiB / 16 million decoded pixels, 12 uploads per hour. Only single-frame raster images are accepted. Output is metadata-free 256×256 WebP in `user_avatars`; returns `{avatarUrl}`. `DELETE /api/profile/avatar` takes `{}` and removes the caller's image. `GET /api/avatars/:userId?v=:version` allows the owner or current shared teammates only; returns private, non-cacheable WebP. Profiles, rosters, video participants and messages include an optional/null `avatarUrl`. Images and credentials must not be committed to the repository.

`POST /api/solo` takes `{}` after demo checkout for a complete solo profile. It atomically creates a private one-member course workspace with no meetings and no matchmaking queue entry, returning `{squadId}`. Existing lesson, quiz, assignment and history endpoints apply, with calendar and sequence enforcement. The sprint starts immediately and lasts four weeks. A second unfinished course is rejected. Squad joins and manual squad creation reject solo preferences. API workspace routes retain the existing `/squads/:id` shape; summaries include `learningMode`.
